# 阶段 3 — 三栏主窗口

目标：把主窗口对齐设计稿与原型，并补齐原型的交互语义。
这是唯一会产生可见变化的阶段，也是验收标准最密集的阶段。

## 前置

- 阶段 1、2 完成（`vaultStore` 出口、`sections` 表、`match_rule`、`expected_updated_at`）。
- **需要拍板**：D-01（快捷键）、D-03（分类口径）、D-04（类型模板）、D-08（断点）、
  D-12（vault 语义）。
  D-08 未拍板时按 C 方案（不动窗口尺寸）执行，3.1 的宽度约束照旧，跳过 3.8。
  D-12 未拍板时**不做 vault 区**（3.2 第 1 条降级为只读显示当前库名），
  避免出现"看起来像隔离"的文案。

## 顺序

```
3.1 布局壳 + 宽度 → 3.2 侧栏 → 3.3 列表 → 3.4 详情只读 → 3.5 编辑会话
                                                              ↓
                        3.7 快捷键/命令面板 ← 3.6 回收站与归档 ←┘
                                            ↓
                                         3.8 响应式（D-08）
```

| 侧栏 | 244 | 200–280 | 是（当前**无**） |
| 条目列表 | 300 | **260–360** | 是 |
| 详情 | fluid | — | — |

- 列表栏现值 220 / 夹在 180–250（`App.tsx:432/828`）与设计稿的 260–360 直接冲突，
  按设计稿改（T-01）。

### 3.2 侧栏

自上而下（design.md §3.2）：

1. **Vault 区**（N-14 / D-12）：当前 vault 名 + 下拉切换 + 新建（用 `Dialog` 替换
   `window.prompt`，`App.tsx:798`）。vault 列表在侧栏，不再只在详情顶栏
   （`App.tsx:1431-1443`）。
   **文案纪律**：全部 vault 共用同一把 `VaultKey`（design.md §0.3 末），所以不得出现
   "独立加密 / 隔离 / isolated"一类词。i18n 里为 vault 区写一条说明句：
   "库是组织方式，全部由同一主密码保护"。
2. **列表内过滤框**（`⌘F`，D-01）。
3. **主导航**：All Items / Favorites / Recent / Synced。当前 5 项
   （vaults, favorites, tags, generator, watchtower，`navigation.ts:7-13`）重排。
   `navigation.ts` 的 `label` / `route` 字段是死数据，删。
4. **Categories**：由 `itemCatalog` 派生，**每行带计数**（N-01）。
   当前 12 行硬编码（`App.tsx:191-204`）与 18 项类型下拉（`380-399`）不一致，
   导致 6 个类型选了之后侧栏无入口。按 D-03 收敛。
5. **Tags**：逐个 tag + 计数（N-07）。当前 "Tags" 导航只是"有任意 tag"
   （`App.tsx:626`）。tag 色按名字 hash 从 8 色低饱和板取（T-07，免迁移）。
6. **Archive / Trash**：各带计数。Archive 现在是侧栏底部一个扁平列表 + 点击即恢复
   （`App.tsx:1317-1338`），改成进入独立视图（3.6）。
7. **底部**：Watchtower 入口、Settings、同步状态（D-06，provider 无关，
   **不显示"已同步"** 除非真的同步过）。

计数来源：`count_items_by_type` / `list_tags_with_counts`（阶段 2.7）。
不要用前端从已加载列表算 —— 归档/回收站条目不在列表里，会算错。

### 3.3 条目列表

行（56px，T-03）：图标 32×32 rounded 8 → 标题 + 副标题 → 右侧 tag 药丸 / 2FA 徽标 /
相对日期。

补齐缺口：

| 项 | 现状 | 改动 |
|---|---|---|
| 图标 | 永远首字母（`App.tsx:1407`），`categoryItems` 的 icon 只在侧栏用 | 用 catalog 的类型图标；**不发网络取 favicon**（T-06） |
| 日期 | `updated_at` 在契约里但 `App.tsx` **零引用** | 相对日期，i18n 化 |
| tag | 列表里从不渲染 | 药丸，最多 2 个 + `+N` |
| 2FA 徽标 | 无 | 有 otp 字段时显示 |
| 搜索行为 | 顶部搜索是独立下拉、`.slice(0,8)` 硬截断、**只匹配标题**、不改列表（`App.tsx:634-638`） | 搜索**原地过滤列表**；把 `list(query)` 的服务端参数真正传下去（`vaultApi.ts:178` 支持但从未用）；匹配扩展到 username/url/tag/notes |
| 排序 | 全应用零 `.sort()`，顺序 = `ORDER BY updated_at DESC` | 列表头排序菜单（名称/更新时间/创建时间），偏好持久化 |
| 分组 | 无 | 本期不做（原型也没有） |
| 键盘 | 无 | `↑↓` 移动选中、`⏎` 进编辑、`Delete` 移入 Archive、`⌘Delete` 移入 Recently Deleted（D-01）；两者都要在输入框聚焦时**让回默认行为**，否则打字会删条目 |
| 列表头 | 无标题行，那栏显示的是数据库状态（`App.tsx:1375-1378`） | 标题 + 计数 + 排序菜单；DB 状态移到同步状态位 |
| 空态 | 只有 `t('vault.noItems')` | 加"新建条目"动作 |
| 虚拟化 | `visibleItems.map` 直接渲染（`1400`） | 条目 > 300 时上虚拟滚动，或明确记录为欠账 |

### 3.4 详情检查器 — 只读态

**本阶段最重要的行为变更**：取消"用一个 `<fieldset disabled={!isEditing}>`
（`App.tsx:1565`）把整个表单灰掉"的做法。

当前只读态下密码的显示/复制/生成按钮**全都是灰的**（`1606-1618`），只有 Edit/Done、
vault 选择器、Archive 可用。这违反"读视图应该能读"的常识。

改为两个显式视图：
- **只读**：所有输入渲染成文本；复制 / 显示密码 / 打开网站 / 复制 OTP **全部可用**；
  密码默认遮罩，`⌘R` 切换、按住 `⌥` 临时全显（D-01）。
- **编辑**：输入可写，动作按钮保留。

区块由 `SectionRenderer` 数据驱动（design.md §3.3 的 10 个区块），不再硬编码 JSX。
D-04 选 A 时只有 `login` 有专属模板，其余类型走通用区块 —— 但渲染路径必须统一，
否则阶段后期每加一个类型都要复制一遍表单。

具体区块要点：

- **主凭据**：熵值 + 强度条（N-10，用阶段 2.9 的 `estimate_password_strength`）。
  设计稿的遮罩点样式（`#48484A` 7px/6px）本期**不做**（T-08），保留原生圆点。
- **一次性密码**：`492 817` 空格分隔（当前是 `•`，`totpDisplay.ts:6`，T-05）+
  最后 5 秒进度由绿转红（设计稿要求，当前只有环形进度无色彩变化）。
  1 秒 ticker 已有（`App.tsx:659-674`），到期自动重取已有（`676-685`）。
- **网站与自动填充规则**：每行 URL + `match_rule` 下拉（阶段 2.2/2.6）。
  加"为什么这个站点没命中"的调试提示（§6.5 降级为 Exact 时尤其需要）。
- **自定义字段与区块**：把手**真的能拖**（N-08）。当前 `☰` 是 `aria-hidden` 装饰
  （`App.tsx:1681-1683`），全仓库无任何拖拽逻辑，而 `item_fields.position` 列早就在。
  拖完提交 position，重开保持。
- **附件**：网格/行 + 拖放上传（D-05 选 A 才有 100MB 上限的底气）。
  当前新建未保存条目时选文件会**静默丢弃**（`App.tsx:943` 仅在条目已存在时挂载）——
  修：编辑会话内允许暂存，保存后一并上传。
- **元数据**：创建/更新时间 + 条目 ID（原型 "Item ID: 9f7b-Github-428"）。
  `created_at` 表里有但没进契约，阶段 2.7 已补。
- **版本历史**：D-10 默认选 A → 放**禁用占位区块**，不实现。
- **错误横幅**：解锁后的详情区当前只有 `success-banner`（`App.tsx:1938`），
  `error-banner` 只存在于锁屏（`1244`）和 Settings（`2320`）。补上（T-14）。

### 3.5 编辑会话（D-02）

按 A 方案：

- `src/state/editSession.ts`：working copy、脏检查、防抖 800ms 写草稿、
  `save()` 带 `expected_updated_at`、`cancel()` 丢弃。
- 顶栏：`取消 / 保存` + "草稿已自动保存 Ns 前"。
- **冲突处理**：`update` 返回 `Conflict` → 提示"此条目在别处被修改"，保留编辑态与草稿，
  给"重新加载"和"强制覆盖"两个动作。扩展 `/save` 会并发改同一条目（`browser_bridge.rs:170`），
  这条路径真实存在。
- **打断保护**：编辑中触发锁屏 / 切 vault / 选另一个条目 → 若有未保存改动，
  弹确认，**不得静默丢弃**。当前 `isEditing` 在选条目时被动翻转（`App.tsx:652-657`），
  改动直接丢。
- 提交失败 → 停留编辑态 + 错误横幅（flow.md §5 的分支表逐条实现）。
- `⌘S` 提交、`Esc` 取消。

### 3.6 归档与回收站视图（N-13）

- Archive 视图：列表 + 恢复 + **移入回收站**。当前 Archive 是侧栏底部点击即恢复的
  扁平列表（`App.tsx:1317-1338`），没有独立视图。
- Trash 视图：列表 + 恢复 + 彻底删除 + 清空。四个 Rust 命令
  （`lib.rs:670-673`）与四个 `vaultApi` 包装（`vaultApi.ts:189-199`）**全部已实现、
  零调用**。30 天到期由阶段 2.5 的 sweep 负责。
- 文案对齐 1Password 语义：Archive 无限期、仅从搜索与自动填充隐藏；Trash 30 天。
  当前 `list_login_items` 已正确排除两者（`vault.rs:515`），桥也走同一函数，
  所以"归档不出现在自动填充"已经成立 —— 不需要新代码，需要的是 UI 与文案。
- **命名用 `Archive` / `Recently Deleted`，不用 `Trash`**（原型对这个区没有任何命名，
  所以不构成冲突）。1Password 文档里这两个词是固定的，且永久删除的动作叫
  `Destroy permanently`、恢复叫 `Restore Item`；照抄可以省掉一层"这是不是同一个东西"的
  解释成本。i18n 的 zh 对应"已归档 / 最近删除"。

### 3.7 快捷键与命令面板（D-01）

当前只有 4 个（`App.tsx:583-604`：`⌘,` `⌘N` `⌘F` `⌘K`，其中 `⌘K` 是锁库）。

按 D-01 表格实现全部 13 组。要点：

- `⌘K` 从锁库**迁走** → `⌘⇧L`。这是肌肉记忆反转，D-01 未拍板前不动。
- `handleLock`（`App.tsx:733-742`）目前只能从 `⌘K` 和空闲计时器到达，
  **界面上没有锁库按钮**。补工具栏锁库按钮。
- 命令面板 = 搜索 + 命令，`⌘K` 唤起，`↑↓` 选、`⏎` 执行、`Esc` 关。
- 快捷键处理器要注册在**窗口级**并处理"焦点在输入框内时哪些键要放行"
  （`⌘C` 在选中文本时不能抢复制）。
- 现有处理器 `if (!event.metaKey) return` 直接短路，`Esc` / `↑↓` / `⌥` 这类
  无 meta 的键根本进不来 —— 要重构判断结构，不是加分支。
- `⌘/` 浮层（阶段 4 建组件，这里先接线）。

### 3.8 响应式（D-08）

选 A：`tauri.conf.json` `minWidth` 960 → 560。

- `<820px`：侧栏转 overlay，`⌘⇧D` 唤出，点外关闭。
- `<560px`：单栏 push/pop 导航栈 —— 详情成为全屏页，返回列表是导航动作而非改 state。
  这是**导航模型变更**，不是 CSS。`selectedId` + `activeNavigation` 要能表达"栈"。
- `styles.css` 当前**零条 `@media`**，全部新增。
- 暗色/亮色在两档宽度下的分隔线、阴影、overlay 材质都要单独看。

选 B：只降到 820，做两栏，单栏留欠账。选 C：跳过本节。
